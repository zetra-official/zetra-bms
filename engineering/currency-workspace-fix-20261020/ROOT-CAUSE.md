# Auth/workspace reliability and Currency UI replacement

The failed deployment `6ad7a771217ce218428b0c64` and restored deployment `6ad76cf47622bc0a29e1244f` were compared without Production writes. The exact failed artifact opened Home/POS after genuine login, and opened successfully when served locally with genuine Supabase Auth. Currency preference hydration was not established as the cause of the hang. The speculative identity/preference experiment is excluded from both release sources.

Confirmed failure paths and scoped corrections:

1. Public bundle transfers were slow/incomplete for both deployments. An interrupted old full-bundle transfer reproduced the static “Loading your workspace…” screen. A small pre-application loader now preserves normal full/compressed delivery, falls back to bounded range retrieval, verifies complete length and SHA-256 before one execution, and exposes a retry while preserving the session. Existing Production range response and security policy were checked read-only. This mitigates interrupted delivery; it does not claim to repair the network/CDN itself.
2. The old bootstrap interpreted a session-read timeout as missing authentication; a late boot result could supersede a newer auth event. Login also cleared session storage for broad “session”/“jwt” error wording. Timeouts/network errors now mean retryable unknown state, only precise terminal refresh rejection permits the existing cleanup, and auth revisions reject late boot results. Expired sessions require SDK refresh; authorization/RLS is not bypassed.
3. Tabs performed an unbounded remote `getUser()` while rendering an empty view. A genuine organization re-selection produced this blank wait, with no JavaScript exception, and eventually recovered. Tabs now use a bounded SDK session/refresh check with visible recovery. This same old path exists in the restored Production source.
4. An in-flight old identity's membership response could commit obsolete rows or process a disabled-account error after a new identity arrived. Generation guards now discard late session, hydration, organization and store responses; a new identity queues a canonical boot and clears volatile workspace state. Current disabled-account policy remains in force. Deferred SDK/RPC tests exercise the actual loader on both platform sources.
5. Canonical membership reads are bounded, transport errors cannot trigger onboarding redirects, and a root render boundary exposes a generic retry instead of an unhandled white screen. Raw exceptions are not displayed.

No customer incident logs or credentials were collected. These are confirmed reproducible/code-level failure paths, not proof that every reported customer logout has the same cause. The read-only Owner Production path passed during observation; intermittent incidents for other customers remain unattributed.

Currency Card placement, Desktop Dashboard, POS 50/50 controls, FX calculations/catalog/policy, Checkout and Catalog source are preserved against the approved Currency UI package. The new release contains seven changed/new Web source paths and six Android paths; full review patches and strict archive hashes are included. No SQL, financial writer, tax feature, activation, dependency or runtime change is included.
